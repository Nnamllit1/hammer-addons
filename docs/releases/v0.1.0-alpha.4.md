Load newly installed add-ons and reload compatible DLLs without restarting
Workshop Tools. This release also adds Steam account and friends support.

## New features

- **Load new add-ons:** discover packages installed while the application is
  running from the manager's Add-ons tab.
- **Reload selected:** replace a running add-on that opts into hot reload.
  Pending jobs or an incomplete DLL build leave the current instance running.
- **Reload SDK and example:** `hammer_reload.h` defines the cleanup contract;
  the `reload_counter` example demonstrates preserving settings across reloads.
  The add-on generator includes a `reload_counter` template.
- **Steam account and friends:** the bundled `steam_context` add-on shows account
  identity, friends and presence, with profile and friends overlay shortcuts
  when available. SDK snapshots and subscriptions are available to add-on authors.

## Update

Close Workshop Tools, extract the Windows x64 ZIP outside CS2, and copy your
custom add-on folders into its `addons/` directory. Start **Launch Workshop
Tools.cmd** and choose a project normally. Updating the framework itself still
requires restarting the tools.

In the **Workshop Add-ons** manager, use **Load new add-ons** after installing
a package, or select a running add-on and choose **Reload selected**.
Hammer keeps the manager under **Help > Workshop Add-ons**.

Existing add-ons remain compatible. Hot reload requires `reloadable=true` in
the manifest and a valid `HA_QueryReload` export; other add-ons still need a
restart after updates. The SDK ZIP includes the new header, example source,
and `docs/HOT_RELOAD.md`.

## Limits

- Reload affects the current process. The project picker and editor have
  separate add-on instances.
- Reloadable packages support one DLL plus data files. Retired DLL images stay
  mapped until process exit, with a limit of 32 generations per add-on.
- If cleanup throws or a replacement fails after the previous instance stops,
  correct the package and restart. Reload does not sandbox native code.
- Steam networking and invitations are not implemented. Overlay shortcuts
  depend on availability in the tools session.
- The native logging provider remains disabled. Automatic Hammer build-output
  capture continues to work independently.

Downloads include the portable Windows x64 package, SDK, release metadata and
SHA-256 checksums. Native add-ons run with your Windows permissions; install
only code you trust.
