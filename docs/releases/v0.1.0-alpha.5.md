Restore launcher compatibility with CS2 builds **25472966** and **25492732**.
If the launcher reports that Asset Browser does not match a supported original
Valve build after these updates, install this package.

## Fixes and improvements

- Added compatibility profiles for both builds after checking Valve signatures,
  x64 architecture, and the required Asset Browser exports and ordinals.
- All bundled example add-ons now support the reload lifecycle.
- Reload uses a verified package snapshot and its captured manifest. Failed or
  declined attempts that never reach native loading clean up their own copies.
- Failed native load attempts count toward the 32-attempt limit per add-on.
- Invalid reload preparation results disable the instance. A veto keeps the
  instance active but cannot undo changes already made by its callback.
- C++ callback exceptions revoke the failed add-on's SDK access and cancel its
  jobs while healthy add-ons continue receiving callbacks.

## Update

1. Close Workshop Tools and the project picker.
2. Extract **hammer-addons-v0.1.0-alpha.5-windows-x64.zip** into a new folder
   outside your CS2 installation.
3. Copy your custom add-on folders from the previous package's `addons/`
   directory into the new package. Keep the updated bundled add-ons.
4. Start **Launch Workshop Tools.cmd** from the new folder. Update existing
   desktop or Steam shortcuts to point to this copy.

Use the complete package; editing `compatibility.json` beside an older launcher
does not update that launcher's compiled compatibility profiles. No Valve files
need to be replaced.

## Validation and limits

The Windows build, native regression suites, and 35 loader integration scenarios
passed locally. The rebuilt launcher's `--check` accepts the installed CS2 build
25492732. A live editor session on that build has not been verified.

Native add-ons remain unsandboxed. Access violations and memory corruption can
still crash the host. Retired DLLs remain mapped until process exit, and unused
cache cleanup is best effort when other programs block deletion. The native
tool-log provider remains disabled; Hammer build-output capture is independent.
